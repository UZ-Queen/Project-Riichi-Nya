## 포기·종료·재시작 동작

### 포기 결과와 기록

| Option | Description | Selected |
|--------|-------------|----------|
| 기존 결과 화면 + 포기 사유 | 현재 결과 흐름을 재사용하면서 종료 원인을 구분 | ✓ |
| 결과 없이 메인 메뉴 | 짧지만 현재 결과를 확인할 수 없음 | |
| 별도 포기 결과 화면 | 구분은 명확하지만 UI 상태 증가 | |
| 현재 거리 표시, 고득점 미갱신 | 미완료 게임의 결과와 공식 기록을 구분 | ✓ |
| 포기도 고득점 갱신 | 현재 코드 동작 유지 | |
| 포기 결과 무효 | 현재 거리도 표시하지 않음 | |

### 재시작 경로와 난수

| Option | Description | Selected |
|--------|-------------|----------|
| 메인 메뉴 복귀 후 기존 시작 버튼 | 기존 메뉴 흐름과 초기화 경계를 재사용 | ✓ |
| 결과 화면에서 즉시 재시작 | 빠르지만 새 버튼·경로 추가 | |
| 자동 재시작 | 메뉴 선택과 결과 확인 기회 없음 | |
| 실제 게임은 새 난수, 테스트만 고정 시드 | 플레이 다양성과 테스트 재현성을 분리 | ✓ |
| 실제 게임도 고정 시드 | 매번 같은 진행 반복 | |
| 시드 선택 UI | Phase 1 범위를 넘는 설정 UI | |

**User's choice:** 포기는 기존 결과 화면에서 구분하고 고득점은 갱신하지 않는다. 메인 메뉴를 거쳐 실제 게임은 새 난수로 다시 시작한다.
**Notes:** 재시작 때 타이머·점수·거리·라운드·손패·하천·UI·이벤트 구독이 모두 깨끗해야 한다.

## 검증 증거 보존 방식

### 커밋할 증거

| Option | Description | Selected |
|--------|-------------|----------|
| 짧은 Markdown 검증 요약만 커밋 | 사람이 읽기 쉽고 raw 출력 잡음을 피함 | ✓ |
| XML·빌드 로그까지 커밋 | 원본은 남지만 경로·시간·대용량 diff가 누적 | |
| 결과를 커밋하지 않음 | 저장소는 깔끔하지만 당시 증거가 없음 | |
| 기준선과 완료 상태를 한 문서에서 비교 | 개선 전후를 직접 연결 | ✓ |
| 완료 PASS만 기록 | 개선 근거가 약함 | |
| 기준선·완료 문서를 분리 | 작은 Phase에서 문서 수 증가 | |

### 검증 주체와 Player 범위

| Option | Description | Selected |
|--------|-------------|----------|
| Codex가 테스트·빌드·GUI 확인, 불확실하면 사용자 확인 | 자동화 가능한 부분은 실행하고 시각 판독은 fail closed | ✓ |
| 사용자가 전체 체크리스트 수행 | 수동 부담 증가 | |
| GUI까지 전부 PlayMode 자동화 | Phase 1 구현 범위 증가 | |
| 빌드→실행→시작→포기→결과→메뉴→재시작 | BASE-03·BASE-05의 최소 end-to-end 경로 | ✓ |
| 위 경로 + 실제 180초 종료 | 반복 검증 시간이 늘고 Phase 1 필수 범위를 넘음 | |

**User's choice:** 기준선과 Phase 1 완료 상태를 비교하는 Markdown 요약 하나를 커밋하고, Codex가 Player 재시작 경로까지 확인한다.
**Notes:** `smoke test`의 의미와 Codex의 GUI 판독 방식을 설명했다. Unity 화면 판독이 불확실하면 에이전트가 추측으로 PASS 처리하지 않고 사용자에게 확인을 요청한다.

## 포기 입력 안전장치

| Option | Description | Selected |
|--------|-------------|----------|
| 타이머가 계속 흐르는 포기 확인창 | 우발 종료를 막으면서 추가 사고 시간을 주지 않음 | ✓ |
| `Esc` 길게 누르기 | 일시정지 악용은 없지만 홀드·진행 표시·취소 상태가 증가 | |
| 일시정지·설정·포기 메뉴 통합 | 미래 설정에는 적합할 수 있으나 현재 범위를 확대 | |

**User's choice:** `Esc` 확인창을 사용하되 게임 입력만 막고 180초 타이머는 계속 진행한다.
**Notes:** 사용자는 일시정지 상태에서 패를 검토한 뒤 타패하는 비정상 흐름을 우려했다. 확인 중 시간이 끝나면 정상 시간 종료가 우선하며, 홀드 입력이나 설정 통합은 실제 필요가 생겼을 때 다시 판단한다.
