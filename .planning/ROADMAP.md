# Roadmap: Project Riichi Nya

## Overview

기존 Unity 솔로 마작의 실행 기준과 고유한 180초 플레이를 먼저 보존한 뒤, 같은 순수 규칙 결과를 사용하는 고정 기본 4인 반장전을 헤드리스 상태 머신부터 Unity 화면까지 수직으로 완성한다. Phase 1-5와 Phase 7은 반드시 출하하는 Stage 2 완료선이다. Phase 6의 사람 후로와 모든 깡은 Stage 2가 전부 검증된 뒤에만 시작하며, 완전한 묶음으로 통과하지 못하면 `CALL-01`~`CALL-18` 전체를 v2로 이동하고 부분 UI 없이 Stage 2를 출하한다.

## Phases

- [ ] **Phase 1: 실행 기준선과 검증 경로** - 기존 솔로 플레이를 재현하고 테스트·Windows 빌드·재시작 검증이 가능한 기준선을 만든다.
- [ ] **Phase 2: 정확한 공유 규칙 코어** - 두 모드가 같은 결정론적 패산·화료·역·부·지불 결과를 사용하게 한다.
- [ ] **Phase 3: 독립 솔로 모드와 완전한 리치** - 기존 180초 점수·부스트·거리 경험을 보존하면서 리치 전 과정을 완성한다.
- [ ] **Phase 4: 헤드리스 고정 기본 반장전** - UI 없이도 한 사람과 쯔모기리 더미 세 좌석의 동1국~남4국 대국을 끝까지 검증한다.
- [ ] **Phase 5: Unity 반장전 통합** - 검증된 반장전을 기존 Unity 실행 흐름에서 선택하고 플레이하고 결과까지 확인할 수 있게 한다.
- [ ] **Phase 6: 사람 후로·열린 손·모든 깡 (조건부 Stage 3)** - 치·퐁·대명깡·암깡·가깡과 관련 규칙을 완전한 단일 묶음으로 제공한다.
- [ ] **Phase 7: 포트폴리오 릴리스와 증거** - Stage 2를 확정 출하하고 Stage 3 공개 여부와 모든 주장을 태그·테스트·빌드·시연으로 증명한다.

## Release Policy

- Stage 2의 고정 기본 4인 반장전은 필수 릴리스 완료선이며 Phase 1-5와 Phase 7을 생략할 수 없다.
- Phase 6은 Phase 1-5의 도메인·통합·Windows 빌드 검증이 모두 통과하고 전체 Stage 3 묶음을 끝낼 여력이 있을 때만 시작한다.
- Phase 6이 모든 성공 기준을 통과하지 못하면 `CALL-01`~`CALL-18` 전체를 v2로 이동한다. 최종 태그에는 부분 후로·깡 동작이나 이를 암시하는 UI를 노출하지 않는다.
- Phase 6을 진행하거나 연기해도 Phase 7의 검증·빌드·증거 작업은 반드시 수행한다.

## Phase Details

### Phase 1: 실행 기준선과 검증 경로
**Goal**: 플레이어와 개발자가 기존 솔로 경험을 반복 재현하고 안전하게 변경 여부를 판별할 수 있다.
**Mode:** mvp
**Depends on**: Nothing (first phase)
**Requirements**: BASE-01, BASE-02, BASE-03, BASE-04, BASE-05
**Success Criteria** (what must be TRUE):
  1. 개발자는 `b18320e`의 annotated baseline tag와 고정 시드·행동 기록으로 같은 대표 솔로 패 진행을 재현할 수 있다.
  2. 플레이어는 같은 실행 세션에서 솔로 게임을 시작하고 정상 종료 또는 포기한 뒤 다시 시작해도 이전 상태나 이벤트가 중복되지 않는다.
  3. Windows Player가 런타임 `UnityEditor` 참조 없이 컴파일되고 실행되어 대표 솔로 경로를 시작할 수 있다.
  4. 개발자는 Unity Test Framework의 프로젝트 EditMode 테스트를 배치 실행하고 결과 파일을 확인할 수 있다.

### Phase 2: 정확한 공유 규칙 코어
**Goal**: 솔로와 4인 모드가 동일하고 정확하며 자동 검증되는 마작 규칙 결과를 사용한다.
**Mode:** mvp
**Depends on**: Phase 1
**Requirements**: RULE-01, RULE-02, RULE-03, RULE-04, RULE-05, RULE-06, RULE-07, RULE-08, RULE-09, RULE-10
**Success Criteria** (what must be TRUE):
  1. 같은 시드는 두 모드에서 동일한 136장 패산을 만들며, 각 TileID 네 장·적5 세 장·모든 합법 셔플 위치가 검증된다.
  2. 규칙 엔진은 일반형·치또이츠·국사무쌍의 모든 완전한 분해를 찾고, 동일한 정체성 규칙으로 중복을 처리해 최종 지불액이 가장 높은 합법 해석을 고른다.
  3. 도라만 있는 손은 화료할 수 없고, 멘젠·후로·화료 맥락에 맞는 역·판·도라·역만 배수·부가 표 기반 사례와 일치한다.
  4. 친·자의 론과 쯔모는 지불자별 금액을 100점 단위로 올림하며, 같은 패와 맥락은 솔로와 4인 모드에서 같은 기본 결과를 만든다.
  5. 교정된 규칙을 사용하는 솔로 모드가 기존 실행 경로에서 계속 시작되고 Windows Player가 빌드·실행된다.

### Phase 3: 독립 솔로 모드와 완전한 리치
**Goal**: 플레이어가 기존의 시간제 조패 게임을 독립된 완전한 플레이 경험으로 계속 즐길 수 있다.
**Mode:** mvp
**Depends on**: Phase 2
**Requirements**: SOLO-01, SOLO-02, SOLO-03, SOLO-04, SOLO-05, SOLO-06, SOLO-07, SOLO-08, SOLO-09
**Success Criteria** (what must be TRUE):
  1. 플레이어는 별도 솔로 모드에서 180초 동안 13장 배패, 쯔모, 타패, 화료 또는 패산 소진 뒤 새 손, 시간 종료의 연속 흐름을 플레이할 수 있다.
  2. 한 번의 솔로 화료는 점수·부스트·이동 거리·최종 거리·고득점에 정확히 한 번 반영된다.
  3. 플레이어는 시간 종료 또는 포기 결과를 확인한 뒤 같은 씬에서 깨끗한 상태로 새 솔로 게임을 시작할 수 있다.
  4. 플레이어는 실제 텐파이를 만드는 타패만 리치 후보로 선택하고, 1,000점 공탁 뒤에는 합법 암깡·화료 외에 쯔모기리만 할 수 있다.
  5. 리치 화료에는 조건에 맞는 일발·우라도라가 반영되고, 유국 리치봉은 다음 손으로 이월되지만 시간 종료 거리 보상에는 포함되지 않는다.

### Phase 4: 헤드리스 고정 기본 반장전
**Goal**: 개발자가 UI와 무관하게 정확한 한 사람 대 세 쯔모기리 더미 반장전을 동1국부터 고정된 남4국 종료까지 실행하고 검증할 수 있다.
**Mode:** mvp
**Depends on**: Phase 3
**Requirements**: TABL-01, TABL-02, TABL-03, TABL-04, TABL-05, DUMY-01, DUMY-02, DUMY-03, DUMY-04, HUMN-01, HUMN-02, HUMN-03, HUMN-04, HUMN-05, HUMN-06, HUMN-07, MTCH-01, MTCH-02, MTCH-03, MTCH-04, MTCH-05, MTCH-06, MTCH-07, MTCH-08, MTCH-09, MTCH-10
**Success Criteria** (what must be TRUE):
  1. 고정 시드 대국은 25,000점 네 좌석, 동가인 사람, 실제 배패·하천·좌석풍·라이브 월·14장 왕패·도라 표시패·턴 주인을 독립적으로 보유한다.
  2. 각 더미는 자신의 쯔모패를 그대로 버리고 기존 13장을 유지하며 어떤 선언이나 화료도 하지 않지만 유국 텐파이 판정에는 실제 손패로 참여한다.
  3. 사람은 자신의 턴에 합법 타패 또는 쯔모를 선택하고 각 더미 타패마다 론·패스 기회를 한 번 받으며, 최소 1역과 자기 하천·일시·리치 후리텐 규칙이 화료 가능 여부를 결정한다.
  4. 잘못된 좌석·지난 반응 창·중복·종료 후 행동은 상태를 바꾸지 않고 거절되며, 리치 공탁·손패 고정·일발·우라도라·리치봉 회수 상태는 명시적인 단계 전이로 처리된다.
  5. 론·쯔모·본장·리치봉·0~4명 텐파이 노텐벌부 정산은 총점을 보존하고, 친 연장/회전과 동1국~남4국 진행 후 남4국 친이 넘어갈 때 미회수 리치봉을 별도 결과로 남기며 종료된다.

### Phase 5: Unity 반장전 통합
**Goal**: 플레이어가 기존 Unity 실행 화면에서 솔로와 고정 기본 반장전을 선택하고, 반장전을 이해하며 끝까지 플레이할 수 있다.
**Mode:** mvp
**Depends on**: Phase 4
**Requirements**: DUMY-05, HUI-01, HUI-02, HUI-03, HUI-04, HUI-05
**Success Criteria** (what must be TRUE):
  1. 플레이어는 메뉴에서 180초 솔로와 4인 반장전을 구분해 시작하고 각각 종료한 뒤 같은 실행 세션에서 다시 시작할 수 있다.
  2. 4인 HUD는 장풍·국·본장·리치봉·남은 라이브 월·도라 표시패를 현재 대국 상태와 일치하게 보여준다.
  3. 플레이어는 네 좌석의 점수·좌석풍·하천과 현재 턴을 볼 수 있으며, 상대 세 좌석은 전략 AI가 아닌 `Tsumogiri Dummy`로 표시된다.
  4. 화료·유국 결과는 화료자·방총자·역·판·부·지불자별 금액과 본장·리치봉 변화를 보여준다.
  5. 플레이어는 Windows 빌드에서 사람 쯔모·타패·론·패스를 거쳐 고정 기본 반장전의 대표 종료 경로를 완료할 수 있다.

### Phase 6: 사람 후로·열린 손·모든 깡 (조건부 Stage 3)
**Goal**: Stage 2가 완전히 안정된 경우에만 플레이어가 치·퐁과 세 종류의 깡을 열린 손 점수까지 포함해 완전하게 사용할 수 있다.
**Mode:** mvp
**Depends on**: Phase 5 quality gate
**Requirements**: CALL-01, CALL-02, CALL-03, CALL-04, CALL-05, CALL-06, CALL-07, CALL-08, CALL-09, CALL-10, CALL-11, CALL-12, CALL-13, CALL-14, CALL-15, CALL-16, CALL-17, CALL-18
**Success Criteria** (what must be TRUE):
  1. 더미 타패 뒤 론 우선의 합법 치·퐁·대명깡 조합과 패스만 제시되며, 치 방향·퐁 재료·후로 뒤 무쯔모 타패·다음 턴·쿠이카에 제한이 정확하다.
  2. 플레이어는 대명깡·암깡·가깡을 합법한 시점에 실행하고, 각 깡 뒤 영상패·라이브 월 꼬리 이동·14장 왕패·깡도라를 유지하며 네 번 제한과 마지막 쯔모 뒤 금지를 지킨다.
  3. 공개 멘츠가 있는 손도 모든 4멘츠 1머리 형태를 평가하며 멘젠 전용 역 제외·열린 탕야오·쿠이사가리와 열린/암 커쯔·깡의 부를 정확히 적용한다.
  4. 영상개화는 쯔모 정산을 사용하고 해저와 중복되지 않으며, 리치 화료는 활성 깡도라에 대응하는 깡우라도라를 공개한다.
  5. 모든 후로·깡은 일발을 종료하고 열린 손의 리치를 막으며, 리치 뒤에는 일반 후로·가깡을 금지하고 구조와 대기가 유지되는 암깡만 허용한다.

### Phase 7: 포트폴리오 릴리스와 증거
**Goal**: 사용자가 실제 제출 태그의 Windows 빌드를 실행하고, 포트폴리오의 모든 개선 주장을 재현 가능한 증거로 확인할 수 있다.
**Mode:** mvp
**Depends on**: Phase 5; Phase 6 only when the Stage 3 gate passes
**Requirements**: PORT-01, PORT-02, PORT-03, PORT-04, PORT-05, PORT-06, PORT-07, PORT-08
**Success Criteria** (what must be TRUE):
  1. 제출 커밋에는 전체 EditMode·필수 PlayMode 결과와 성공한 Windows x64 `BuildReport`가 보존되어 있다.
  2. 최종 태그의 Windows 빌드에서 플레이어는 솔로와 공개된 고정 기본 반장전의 대표 경로를 완료할 수 있다.
  3. README와 짧은 시연 영상은 실행·테스트 방법, 고정 규칙, 알려진 제한, 기존 솔로 경험, 교정 규칙, 쯔모기리 더미 진행과 사람의 쯔모·론을 실제 빌드와 일치하게 보여준다.
  4. baseline과 최종 tag의 diff가 중복 소스 폴더 없이 재현되고, 대표 3~5개 AI 개발 기록이 문제·원인·제안·사람의 판단·구현·검증을 연결한다.
  5. Stage 3는 치·퐁·세 깡·열린 손 점수·왕패 불변식이 모두 검증된 경우에만 노출되며, 그렇지 않으면 `CALL-01`~`CALL-18` 전체가 v2로 이동하고 부분 후로 UI가 없는 Stage 2가 최종 태그가 된다.
